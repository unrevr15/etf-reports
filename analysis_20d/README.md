현재 설정: **10영업일** (`collect.py`의 `NDAYS=11` → 스냅샷 11개 = 변동 10일). 숫자만 바꾸면 기간 변경.

## 계산식
- **순유출입(①)** = (상장좌수 t − 상장좌수 t−1) × NAV
  → 주가 등락 효과를 뺀 **순수 설정/환매 금액**. AUM 변화와 다름(AUM엔 주가효과 포함).
- **순매수금액(③, ②의 부가표시)** = 1CU 수량변화 × 종가 × 전체CU수 (전체CU수 = 상장좌수 ÷ CU크기)
  → **운용사의 리밸런싱 매매(유량)**. 설정/환매로 인한 기계적 매매는 포함되지 않음(그건 ①이 담당).
- **보유비중(②)** = 테마 보유액 ÷ 액티브 4종 주식 보유액 합계
  → **실제 포지션(저량)**. 매매 + 주가등락이 함께 반영됨. 설정/환매는 전 종목이 비례 증감하므로 비중엔 영향 없음.
  ※ 유량과 저량은 다름 — 예: 전력·에너지는 보유액 247억(3.4%)뿐인데 10일 순매수 +122억(보유액의 절반을 새로 담음).
- 날짜 정합: PDF(t)는 t−1 종가 기준이므로 좌수·종가도 t−1 것을 사용.

## 테마 분류 (`themes.py` — 여기만 고치면 재분류됨)
- **업종 자동 매핑**: 제약·생물공학·건강관리 → 바이오 / 반도체·디스플레이 장비 → 소부장 / 에너지장비 → 전력·에너지
- **종목 수동 지정**(업종을 가로지르는 테마): 심텍·고영·원익머트리얼즈 등 반도체 공급망 → 소부장,
  에코프로·대주전자재료·나노신소재 등 → 2차전지, 레인보우로보틱스·에스피지 등 → 로봇,
  지엔씨에너지·채비 → 전력·에너지
- **판단이 갈리는 종목은 `AMBIGUOUS` dict에 사유와 현재 배치를 명시**(서진시스템·LS머트리얼즈·비나텍·솔브레인 등).
  옮기려면 `OVERRIDE`에 한 줄 추가하고 `python charts.py` 재실행.

## 데이터 출처
- KRX OpenAPI: ETF 일별(좌수·NAV·순자산), 코스닥 종목 일별 종가
- 운용사 PDF(액티브 7종): 1CU 구성종목 수량·평가금액
- 네이버 금융: 종목 → 업종(섹터) 매핑
  ※ KRX API의 `SECT_TP_NM`은 업종이 아니라 소속부(벤처기업부 등)라 사용 불가

## 대상 (universe.py에서 정의)
**액티브 = 코스닥액티브만.** 바이오 전문 액티브(KoAct 바이오헬스케어, TIME K바이오, RISE 바이오TOP10,
TIGER 기술이전바이오, ACE K바이오코스닥)와 커버드콜·채권혼합은 제외.

| ETF | 순자산 | ① 자금흐름 | ②③ 섹터·종목 |
|---|---|:--:|:--:|
| KoAct 코스닥액티브 | 4,306억 | ✅ | ✅ |
| TIME 코스닥액티브 | 2,467억 | ✅ | ✅ |
| TIGER 코스닥액티브 | 336억 | ✅ | ✅ |
| PLUS 코스닥150액티브 | 281억 | ✅ | ✅ |
| DS 코스닥액티브 | 238억 | ✅ | ❌ |
| MIDAS 코스닥액티브 | 59억 | ✅ | ❌ |

- **①**은 KRX 좌수·NAV만 쓰므로 코스닥액티브 6종 전부 + 코스닥 패시브 14종 커버.
- **②③**은 일자별 PDF가 필요한데 DS·MIDAS는 자체 사이트에 날짜별 PDF가 없고
  WiseReport는 **최신일만** 제공 → 히스토리 불가로 제외. 4종 합계는 코스닥액티브 AUM의 **96%**.
- TIGER 코스닥액티브는 ISIN을 규칙(`KR7`+단축코드+`00`+체크숫자)으로 산출, CU=10,000은 좌수 정수검증으로 확정.

## 알려진 제약
- 최신일 KRX 순자산총액이 0으로 오는 경우가 있어 `좌수 × NAV`로 보정(엑셀에 출처 표시).
- 운용사 서버가 짧은 시간 대량 조회 시 **HTTP 429(rate limit)** 로 막을 수 있음.
  → `retry_pdf.py`가 지연을 두고 재시도. 그래도 막히면 시간을 두고 `python run_all.py` 재실행.
  (차트 하단에 결측 ETF가 명시됨 — 현재는 결측 0)

## 재실행
```
python run_all.py
```
캐시(`*.json`)에 없는 날짜/종목만 새로 받으므로 빠름. 기간을 바꾸려면 `collect.py`의 `NDAYS` 수정.

## 차트 가독성 설계 (2026-08-09 개편)
초기 버전은 ②가 "일간 스택막대 + 6라인 누적 + 합계막대" 3패널이었는데 다음 문제로 재설계:
- **y축 압축**: 소부장 하나가 축 폭 633억을 만들어 2차전지·기타·로봇은 화면의 7~12%만 사용 → 4개 라인이 일직선으로 보임
- **스택 지배**: 하루 막대의 최대 조각이 평균 56%·최대 95%, 3억 미만 조각 16/120칸은 보이지 않음
- **정보 중복**: 합계는 누적의 끝점과 같은 값인데 패널을 따로 씀
- **색 규칙 2개**: 위는 테마 고유색, 아래는 매수빨강/매도파랑 → 같은 항목의 색이 바뀜
→ **결론 막대(정렬) + 테마별 소형다중(각자 축)** 으로 교체, 색은 매수/매도 다이버징 하나로 통일.
업종 세분류(25개)는 색 분류 한계(~7개)를 넘어 차트 대신 **엑셀 표**로만 제공.
